# The Wiki Service

This site is a **Docusaurus 3.10.2** docs-only site in `wiki/`, served at `/`.

| Piece | Where |
|---|---|
| Pages | `wiki/docs/**` (Markdown/MDX); folders = sidebar categories (`_category_.json`) |
| Config | `wiki/docusaurus.config.js`, `wiki/sidebars.js` (autogenerated), `wiki/src/css/custom.css` (brand colours) |
| Images | `wiki/static/img/**` |
| Reference tools | `wiki/tools/gen_tags.py`, `gen_perspective.py`, `gen_scripting.py`, run by `gen_all.py` |
| Staleness check | `wiki/tools/check_docs.py` |
| Search | `@easyops-cn/docusaurus-search-local` (offline, no Algolia) |
| Diagrams | `@docusaurus/theme-mermaid` (fenced `mermaid` blocks) |

## Run It

```powershell
cd wiki
npm install            # first time (or after package.json changes)
npm start              # live-reload dev server on http://localhost:3030 (search is NOT available in dev mode)
npm run build          # production build into wiki/build (builds the search index)
npm run serve          # serve the build on http://localhost:3031, search works
```

Or as a container (search works, rebuild on restart):

```powershell
docker compose up -d --build wiki      # first time
docker restart bh-wiki                 # rebuild after doc changes
docker logs -f bh-wiki                 # watch the build
```

The `bh-wiki` container mounts `./wiki` at `/app`, keeps its own `node_modules` in the volume `bh-wiki-node-modules`,
reinstalls only when `package-lock.json` changes, builds into `/tmp/wiki-build` with its own generated-files folder
(`.docusaurus-container`, so it never collides with a host build), and serves on port 3000 → host **3030**. Stop
`npm start` on the host before starting the container, since both want port 3030.

## Search

- Press <kbd>Ctrl</kbd> + <kbd>K</kbd> or click the search box. Results show the page and the matching section.
- Opening a result highlights the search words on the page (`highlightSearchTermsOnTargetPage`).
- The full results page is `/search?q=<words>`.
- Every page is indexed, including the generated reference pages, so tag paths, view paths and function names are
  searchable.
- The index is built at `npm run build` time; the dev server (`npm start`) has no index.

## Broken Links

The build is **strict by default**: a broken link, anchor, markdown link or image is a build error, so `npm run build`
(and `docker restart bh-wiki`, which rebuilds) fails until it is fixed. Fix the link rather than silencing it. For a
throwaway draft build only, downgrade them to warnings:

```powershell
$env:WIKI_STRICT_LINKS = '0'; npm run build
```

## Partial Builds

When several people write at once, a half-finished folder can break the build. Build only some folders:

```powershell
$env:WIKI_INCLUDE = 'gateway/**,tags/**'; npx docusaurus build --out-dir build-mine
```

To build in parallel with someone else in the same checkout, also give your build its own generated-files folder:
`$env:DOCUSAURUS_GENERATED_FILES_DIR_NAME = '.docusaurus-mine'` (`.docusaurus-*` and `build-*` are gitignored).
